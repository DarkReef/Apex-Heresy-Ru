## Совместимость и CI

Матрица установленных модулей и прочитанных исходников: [module-compatibility-audit.md](module-compatibility-audit.md). Сохранены существенные ограничения: стандартный MAT Hurt/Heal не соответствует модели ран OW; запросы Monk’s TokenBar не являются готовым OW-адаптером; автоматические визуализации без системного адаптера и взаимодействие Aura Effects с индивидуальным `effectClock` требуют отдельного сценария.

Оба workflow синтаксически разобраны PyYAML `BaseLoader`, который сохраняет ключ `on` строкой. Дополнительно проверены матрица Node 22/24, полный coverage-прогон, загрузка артефактов и условия релизного workflow. Manifest имеет собственный ID `apex-heresy-ru`; ссылка ZIP соответствует его версии; файл release notes существует. Workflow релиза создаёт **черновик**, готовые assets не перезаписывает.

Это статическая проверка YAML и контрактов, а не результат исполнения GitHub Actions. Удалённый CI конкретного итогового коммита должен пройти после последней правки.

## Условия решения о релизе

1. Зафиксировать окончательный commit кандидата 1.7.1 и согласовать manifests/download/release notes отдельных пакетов.
2. Получить зелёный полный прогон и удалённый CI Node 22/24 на этом коммите. После runtime-правки повторить затронутые проверки и обновить итоговые артефакты.
3. Заполнить живую матрицу выше результатами с конкретными ролями/версиями и кодом кандидата. Невыполненный или ограниченный сценарий обозначить явно.
4. Проверить установочный архив и manifests скачиванием обратно и совпадением SHA; сохранить разделение системы и модулей.
5. Если остаётся воспроизводимый P1 либо не подтверждена критическая клиентская цепочка, оставить кандидат/предрелиз. Статус stable допустим только для подтверждённого состава и явно указанной области совместимости.

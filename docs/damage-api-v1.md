# Подтверждаемый урон Only War — API v1, кандидат 1.5.6

Исходный commit ядра: `32b1ef886eccba8590f34619af024b637c54cc61`.
Рабочая ветка: `codex/ow-damage-confirmation`. Изменения не слиты и релиз не опубликован.

## Что реализовано

Ядро владеет расчётом и журналом. Smart Assessment 0.3.0 предоставляет карточку,
редактирование решения GM и подтверждение. `Actor.previewDamage` и OW-ветка
`Actor.applyDamage` используют один `planOWDamage`; модуль калькулятор не дублирует.
Другие книги сохраняют прежнюю арифметику и движок последствий.

Поддержаны обычный OW Actor/NPC, одна закреплённая цель Token UUID и её реальный
Actor UUID, в том числе synthetic Actor. Уже выпавшие попадания обрабатываются
последовательно по локациям. Итоговый профиль оружия/боеприпаса, кости, СУ и
RF читаются из сохранённого результата, без перебросов и повторного наложения модификаций.
Новый снимок профиля хранит `damageProfileVersion`, weapon/ammunition UUID,
итоговые traits и список неопознанных текстовых качеств. Старая карточка без метаданных
требует ручного подтверждения конечных повреждений.

Pen снимает только AP; Felling снимает только прибавку Unnatural Toughness для
текущего попадания. True Grit уменьшает новую положительную критическую часть
скорректированным БВ до минимума 1. Уже накопленные повреждения не уменьшаются.
RF остаётся отдельным эффектом; полностью поглощённое RF-попадание причиняет 1
повреждение. Сохранённые кости/СУ, включая штатную замену кости СУ, не пересчитываются.

OW Unnatural `+X` увеличивает бонус характеристики и успешные СУ (`ceil(X/2)`),
не порог теста. Провал остаётся провалом. Подготовленное поле/AE является
авторитетным источником; Item не добавляет эту же особенность второй раз.
Если поле пусто, поддержан структурированный Item-флаг
`flags.dark-heresy.unnatural = {characteristic: "toughness", value: 3}` и
канонический именованный trait с рейтингом. Неопределённый trait без рейтинга
не становится придуманным значением. Старый OW multiplier не конвертируется в +X автоматически.

Сохранённые счётчики: `wounds.value` — полученный обычный урон, `critical` —
накопленный критический. Остаток `max - value - critical` может быть отрицательным.
При записи применяются дельты к исходным счётчикам, без запекания AE в базовые данные.

## Публичный API

После ready: `game.darkHeresy.api.damage.version === 1`.

```js
// Игрок владеет атакующим, но не обязан владеть целью. Нужен активный GM.
const request = await game.darkHeresy.api.damage.request({
  messageId: damageMessage.id, tokenUuid: targetToken.uuid, actorUuid: targetToken.actor.uuid
});
// Детали доступны только активному GM. Preview ничего не записывает и не бросает.
const preview = await game.darkHeresy.api.damage.preview({requestId: request.id});
const decision = {reactionReason: "Реакция уже потрачена"};
const ready = await game.darkHeresy.api.damage.preview({requestId: request.id, decision});
const receipt = await game.darkHeresy.api.damage.commit({
  requestId: request.id, expected: ready.fingerprint, decision
});
await game.darkHeresy.api.damage.getReceipt(receipt.id);
```

Связанный штатный Evasion снимает pending-defense только при совпадении Token/Scene
в его записанном результате. При отсутствии такого подтверждения GM задаёт
`reactionReason`. Карточка не предлагает молча считать отсутствие найденного броска отказом от реакции.

Работающее отражающее поле разрешаются отдельной командой
`resolveField({requestId, expected, decision})`. Она сохраняет намерение, броски,
перегрузку, затем возвращает новый preview/fingerprint. Preview не бросает поле.
Для очереди требуется `fieldMode: "per-hit"` и непустой `fieldReason`: общий текст
книги говорит об атаке, отдельного однозначного указания для всех очередей в доступном
источнике не найдено. Решение о броске на каждое попадание принимает и записывает GM.
Успех по одному попаданию не отменяет автоматически остальные; после перегрузки поле
не бросается повторно. Розарий/преобразующее, переносное, силовое поле с особыми исключениями,
несколько активных полей и неизвестные параметры требуют ручного решения.

Ручные значения — конечные повреждения после всех защит и True Grit; повторного
вычета True Grit в этом режиме нет. Исходная разбивка остаётся предварительной.

Для ручного обхода поля: `fieldWaived: true`, `fieldReason`. При изменённом итоге
нужен `manual: {"<rootId>:hit-0": 5, ...}` для **всех** попаданий и `reason`.
Критические эффекты/RF требуют `criticalReason`; GM может назначить явно выбранные
штатные состояния через `effects: [{condition: "prone", rounds: 1}]`. Их ID,
намерение и факт создания/переиспользования записываются в журнал.

Штатный `api.applyDamage({messageId})` сохраняется: при активном Smart Assessment
и OW он создаёт запрос подтверждения (единственная записанная цель выбирается по UUID;
при нескольких возвращается `target-required`). Без модуля работает прежний интерфейс.
Новый claim учитывается штатным сокет-обработчиком и контекстным применением из чата.
Прямой вызов `Actor.applyDamage` без связи с атакой — общий низкоуровневый метод;
он не обещает идентификатор/идемпотентность произвольного стороннего скрипта.

## Права, состояния и приватность

Исполнитель — только активный GM. Инициатор запроса берётся из сохранённого
`ChatMessage.author`, а не payload.userId. Проверяются видимость исходной карточки,
владение атакующим, оригинальные родительские сообщения, конкретная цель и ruleset.
Повреждения берутся из native flags, никогда из HTML. Fate replacement инвалидирует
неприменённый результат. Применённая квитанция не откатывается автоматически.

Очереди по root attack и фактическому Actor работают **на одном клиенте активного GM**.
Они не являются распределённой блокировкой. Сохранённый claim и минимальный
Actor-маркер защищают повтор после reload и пересечения со штатным обработчиком.
Одна атака в v0.1 может быть применена один раз к одной цели; несколько независимых
карточек урона от одной атаки, двойное оружие и распределение очереди между целями
требуют отдельного расширения.

Preview содержит SHA-256 fingerprint относящегося к расчёту состояния, эффектов и
снимка броска. Commit повторно проверяет его, включая этап прямо перед записью.
Изменение возвращает stale и требует свежего подтверждения. Намерение сохраняется
до поля/ран, результаты поля — до изменения перегрузки. Wounds и маркер квитанции
записываются одним Actor.update; остальные документы меняются последовательно.
Состояния журнала: pending, processing, applied, needs-review. Неоднозначный сбой
помечается needs-review и не повторяется автоматически, даже если ответ записи потерян.
Сбой отображения чата после ран сохраняет applied.

**Whisper и CSS сами по себе не используются как защита flags.** Подробная квитанция
шифруется AES-GCM: в ChatMessage лежат только version/IV/ciphertext; в Actor и исходном
броске — неприватные маркеры. Публичное уведомление не содержит AP, БВ, остатка ран
или имени скрытой цели. Расшифровка выполняется локально только API активного GM.
Требуется защищённый контекст HTTPS/localhost с WebCrypto; при его отсутствии
операция прекращается до записи. Ключ хранится в клиентской настройке текущего GM-браузера и не передаётся в документы.
Другой браузер/GM без этого ключа получает needs-review; журнал не воспроизводится
вслепую. Это сознательная граница v0.1: передачи ключей между GM и экспорта восстановления
пока нет. Не удаляйте клиентское хранилище, если нужны подробные старые квитанции.

Полного Undo нет. Критические таблицы **не** заменяются универсальным порогом смерти.
Новый сервис записывает точно рассчитанные раны; строку таблицы и её последствия
выбирает GM. Неизвестные on-hit свойства (Toxic, Flame, Shock, Corrosive, Concussive,
Snare и др.), психосилы, Blast/AoE, техника, орды, корабли и другие rulesets не
автоматизируются. Daemonic — отдельная защита: исключения для force/holy/psychic/
демонического атакующего требуют подтверждения; Warp Weapon требует проверки
исключений брони и не игнорирует БВ/поле. Непроверенное взаимодействие — needs-review;
ручной итог помечается явно, исходная разбивка сохраняется как предварительная.

## Источники и проверки

Прочитана загруженная русская книга OW Rus 1.05, PDF 140, 152–154, 164, 168, 194–195, 401,
и официальная [Living Errata v1.0](https://images-cdn.fantasyflightgames.com/filer_public/22/bd/22bdda40-d2fa-4bef-8865-99893c848042/igp03_only_war_living_errata_v1_0_hqfin.pdf)
(6 страниц), включая FAQ о Felling/True Grit. PDF не входит в поставку.

Автоматически: системная регрессия и сквозные фиксированные броски от player request
через настоящие новые API/методы Actor до persisted receipt. Документы/сеть моделируются.
Браузерный E2E использует три изолированных контекста, настоящий UI модуля и новый
API ядра с in-memory document host. Он не является живой серверной сессией Foundry.
**Живой multiplayer QA не выполнен.** Manifest verified не является доказательством QA.

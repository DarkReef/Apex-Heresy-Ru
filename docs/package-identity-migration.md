# Переход Apex Heresy RU на собственный ID

Начиная с 1.6.0 пакет называется `apex-heresy-ru`. Старый ID `dark-heresy` принадлежит в реестре Foundry системе Vendare Dark Heresy 2E. Foundry 14 может выбрать её при обновлении, даже если manifest установленного форка ссылается на DarkReef. Замена одной ссылки эту коллизию не устраняет.

## Установка и перенос существующего мира

1. Остановите Foundry. Сохраните **полную копию каталога мира**, включая базы данных. Если мир уже запускался в Vendare, используйте копию до того запуска: этот перенос не отменяет миграции чужой системы.
2. Установите Apex Heresy RU как отдельную систему через manifest:
   `https://github.com/DarkReef/Apex-Heresy-Ru/releases/latest/download/system.json`.
   В новом manifest должен быть `id: apex-heresy-ru`; установка располагается в `Data/systems/apex-heresy-ru`. Старую систему пока не удаляйте.
3. Обновите расширения: ItemPileFFG 0.2.2+, Riftan Charbar 0.1.5+, Riftan Smart Assessment 0.3.1+. Они поддерживают новый ID и прежние выпуски Apex с ID `dark-heresy`.
4. Снова остановите Foundry. Запустите поставляемый `tools/Move-ApexWorld.ps1` для **конкретного мира Apex**, сначала без изменения:

   ```powershell
   pwsh -File .\Move-ApexWorld.ps1 -WorldPath "C:\FoundryData\Data\worlds\my-apex-world"
   ```

   Затем, проверив показанный путь, название и резервную копию всего мира:

   ```powershell
   pwsh -File .\Move-ApexWorld.ps1 -WorldPath "C:\FoundryData\Data\worlds\my-apex-world" -Apply -ConfirmApexWorld -FoundryStopped
   ```

   Скрипт сохраняет отдельную копию `world.json` и меняет только его верхнеуровневое поле `system`. Он не изменяет базы, название мира, ID документов или `systemVersion`. Последнее отражает выполненную миграцию, а не желаемую версию пакета. Не применяйте скрипт к настоящим мирам Vendare.
5. Запустите Foundry и войдите мастером. Система переводит старые ссылки на свои изображения и компендиумы на новый префикс. Не закрывайте мир до окончания переноса. После ошибки перенос можно повторить: отметка завершения записывается только после успешной обработки.
6. Проверьте лист Only War, раны, инвентарь с контейнерами, оружие, бросок из Charbar и подтверждение урона. Убедитесь, что сохранились выбранные правила, настройки и содержимое предметов.

Пользовательский код макросов автоматически не переписывается. В макросах со строками `systems/dark-heresy/` или `Compendium.dark-heresy.` замените только ссылки на ресурсы **Apex**, а не названия флагов. Системные наборы поставляются уже с новыми путями; записи и перевод книг не меняются.

## Что сохраняется

- Данные актёров, предметов, контейнеров, ран и боевых операций; собственные ID документов.
- Пространство хранения `flags.dark-heresy` и настроек `dark-heresy`: это совместимые имена данных, а не ID устанавливаемого пакета. В новой системе флаги читаются напрямую, запись идёт штатным `document.update`, без запрещённого `getFlag` для неустановленного пакета.
- CSS-классы, имена листов, API `game.darkHeresy` и события расширений.
- Ключи правил `dh2`, `ow`, `bc`, `rt`, `dw`. Переименование пакета не переключает правила персонажей.

Меняются ID устанавливаемого пакета, его socket-канал, пути ресурсов и префикс коллекций Babele/компендиумов. Настройки модулей остаются в их собственных пространствах.

## Откат

До первого запуска мира достаточно вернуть сохранённый `world.json`. После запуска используйте полную копию мира и соответствующую старую версию Apex. Не запускайте восстановленный мир в Vendare. Скрипт не пытается отменять миграции баз данных.

# Only War: оставшиеся раны и терминология

## Семантика ран до изменения

`system.wounds.value` хранит полученный обычный урон (0 означает отсутствие урона); `max` — запас ран, `critical` — критический урон сверх запаса. `previewDamage`, `applyDamage`, `combat/vitals.mjs`, лечение за Судьбу и таблицы критических эффектов используют именно эту семантику. NumberField DataModel не имеет ограничения `min:0`; прежняя проблема не была ограничением HTML. Отрицательный полученный урон не является отрицательным остатком здоровья.

## Принятое решение

По согласованию с пользователем внутренние поля сохраняют смысл. Только листы Only War показывают редактируемый остаток `max - value - critical`. Ввод −5 при максимуме 10 записывает `{value:10, critical:5}`. Показатель переживает сохранение и восстановление Actor без изменения схемы мира. Другие rulesets показывают прежний счётчик полученного урона.

Ввод связан с отдельным обработчиком листа, а не с прямым `name=system.wounds.value`; это исключает ошибочное сохранение отрицательного остатка как отрицательного урона. При наличии Active Effects редактируется исходный остаток, а изменённый эффектами показывается рядом и в подсказке. Эффекты не запекаются в исходные данные при повторном сохранении. Числовые изменения `value`/`critical` продолжают означать изменения полученного урона. Отрицательные числовые значения эффектов допустимы; вычисленное `remaining` не добавлено как редактируемое поле эффекта.

`woundsAfterDamage` и `woundsAfterHealing` сохраняют исходные правила: урон после исчерпания запаса увеличивает `critical`, лечение снимает критический урон перед обычным. Переход остатка через 0 получается из этих же полей. Числового универсального порога смерти не вводится: смерть по-прежнему определяют критические эффекты правил. Визуальные проценты ограничены 0..100; сохраняемые данные не обрезаются.

Health Estimate получает свежую долю оставшихся ран с учётом критического урона; только визуальная доля ограничивается 0..1. Миграция старых значений отсутствует. Старые персонажи, созданные с ошибочно заполненным счётчиком урона, не лечатся автоматически: задать желаемый остаток может владелец листа.

Мастер создания теперь записывает полученный запас в `max`, начальный урон — 0. Выдача/отмена бонуса ран происхождения меняет максимум и не наносит/лечит урон. Это исправление поддерживает прежнюю семантику, не меняя данные существующих миров.

## Терминология

`script/localization/field-terms.mjs` задаёт OW-подписи характеристик и поисковые алиасы. API `game.darkHeresy.localization.characteristicTerm(actor,key)` учитывает правила персонажа и язык. Подготовка характеристик Actor и мастер создания используют тот же источник; листы, диалоги, подсказки и карточки читают подписи подготовленного Actor. Smart Assessment использует API, сохраняя технические ключи. Для остальных rulesets сохраняются их исходные подписи, глобальный словарь не переименовывается в этой задаче.

## Инвентарь

Дерево контейнеров и шаблоны реализованы в отдельном ItemPileFFG 0.2.0. Системный `gear.hbs` сохраняет штатные строки, действия и DnD, добавляя значки предметов; модуль декорирует эти строки. Система не содержит полей экономики и кода модулей. Расчёт нагрузки исправлен для количества 0, каждый физический предмет учитывается один раз.

## Проверка и границы

Автоматические тесты проверяют преобразование −1/−5, сериализацию, переходы через 0, реальный обработчик листа и подготовку полосок в VM, правила терминологии, происхождения и полную регрессию системы. Браузерный стенд использует настоящие шаблоны и модули, но имитирует хранилище Foundry.

Живой smoke test Foundry VTT 14 не выполнен: тестовый сервер/мир не предоставлен. Особенно требуется проверить права GM/владельца, синтетические токены, компендиумы, Active Effects и сетевые транзакции Item Piles. Основные листы остаются ActorSheet V1; перевод книг и компендиумов не меняется.

## Панель здоровья токена

Для OW привязки bar1/bar2 к wounds, wounds.value или wounds.remaining показывают остаток ран, включая отрицательный. Изменение ресурса через Actor.modifyTokenAttribute преобразуется в прежние поля полученного и критического урона без нижнего ограничения остатка. Другие наборы правил и ресурсы делегируются Foundry. Максимум остатка ограничен максимумом ран. Стандартная трактовка относительного ввода HUD сохраняется; прямой вызов modifyTokenAttribute с isDelta=false задаёт абсолютное значение.

Изменение ручного счётчика не запускает дополнительные броски критических эффектов; существующий путь применения боевого урона сохранён. Живую проверку ввода HUD, привязанных/непривязанных токенов и графической полосы ещё требуется выполнить.

# Панель отделения, торговля и рюкзаки — 1.5.0

Ветка `codex/party-bar-item-piles` основана на ветке русификации. Это встроенное расширение Apex Heresy RU, не универсальный модуль для других систем. Monk's TokenBar для работы не требуется.

## Панель и проверки

Откройте панель кнопкой с людьми в инструментах токенов или макросом:

```js
game.darkHeresy.party.open();
```

Панель показывает назначенных игрокам персонажей, доступные токены персонажей на сцене и выбранные токены. Мастер видит отделение; игрок — своих персонажей. У независимого токена используются его Actor UUID и показатели. Показаны **полученные** ранения, критические ранения, усталость, судьба и активные состояния. Лист, инвентарь и управление состояниями открываются из панели. Данные обновляются при изменениях документов.

Мастер отмечает участников и выбирает характеристику либо обычный навык, модификатор и причину. В чате появляется сохраняемый запрос с кнопками для владельцев. Бросок проходит через системный `rollTest`; первый допустимый ответ учитывается в сводке. Мастер может закрыть запрос. Результаты сохраняют текущий режим видимости бросков; скрытые результаты не раскрываются в общей сводке. Специализации навыков и противоборства отдельным запросом пока не поддерживаются.

```js
await game.darkHeresy.party.requestChecks({
  actorUuids: canvas.tokens.controlled.map(t => t.actor.uuid),
  characteristic: "agility", modifier: 10, reason: "Перепрыгнуть траншею"
});
```

## Торговля через Item Piles

Нужны совместимый с Foundry 14 выпуск Item Piles и его зависимости libWrapper/socketlib. Система регистрирует адаптер через `game.itempiles.API.addSystemIntegration` на `setup`, до проверки настроек Item Piles. Адаптер заменяет неполную исходную интеграцию `dark-heresy`: типы предметов, количество, цены, сходство, валюту и обработчики контейнеров.

| Данные | Поле |
|---|---|
| Кошелёк персонажа/торговца | `system.economy.credits` |
| Цена за единицу или заполненный комплект | `system.price` |
| Количество | `system.quantity` |
| Контейнер | `system.inventory.isContainer` |
| Родительский предмет | `system.inventory.containerId` |
| Вместимость содержимого в кг | `system.inventory.capacity` |

Это дополнительная денежная экономика. Она не заменяет Влияние, Снабжение и приобретение по правилам разных книг. **Цены назначает мастер; доступность не пересчитывается в деньги. Исходные предметы имеют цену 0**, поэтому перед открытием торговца настройте его ассортимент и цены.

Выберите токен торговца и нажмите «Сделать выбранные токены торговцами». Настройки запасов, торговых коэффициентов, бесконечного ассортимента, индивидуальных цен и сама покупка/продажа остаются в интерфейсе Item Piles. Кошелёк редактируется мастером в новом инвентаре; владельцы настраивают предметы своих персонажей. В существующих мирах, где настройки Item Piles менялись вручную, проверьте соответствие путей таблице выше: пользовательские настройки модуль может сохранять.

## Вложенные предметы

Откройте «Рюкзаки и торговля» из панели либо из заголовка листа персонажа. «Новый рюкзак» создаёт обычный предмет `gear`, вместимостью 20 кг. Через «Настроить» любой физический предмет можно назначить контейнером, задать вместимость, цену и количество. Контейнер всегда представлен одним экземпляром; вместимость 0 снимает ограничение.

Выберите родительский контейнер в строке предмета. Допускаются вложенные сумки; циклы запрещены. Проверяется вес содержимого во всех родительских контейнерах. Вес рюкзака и каждого вложенного предмета входит в общий вес ровно один раз, нулевой остаток боеприпасов веса не добавляет. Если контейнер удалён обычным листом, оставшиеся предметы доступны в инвентаре как предметы без действующего родителя.

```js
const actor = canvas.tokens.controlled[0].actor;
game.darkHeresy.party.openInventory(actor);
await game.darkHeresy.party.moveItem({
  actorUuid: actor.uuid, itemId: "ITEM_ID", containerId: "BAG_ID"
});
```

Строки нового инвентаря можно перетаскивать в Item Piles. При переносе/выбрасывании рюкзака Item Piles получает всё поддерево предметов. При назначении новых ID восстанавливаются все уровни вложения. Контейнеры и их содержимое не склеиваются с другими экземплярами.

При покупке/продаже заполненного рюкзака он является **одним комплектом по цене самого рюкзака**. Цены содержимого не добавляются автоматически. Обработчик документированного `item-piles-preTradeItems` дополняет подготовленные изменения продавца и покупателя до записи: переносит всё содержимое и пересвязывает ID. Для бесконечного ассортимента создаётся копия комплекта. Одновременная продажа комплекта и его содержимого отдельными позициями отклоняется.

## Проверка и ограничения

Автоматические тесты проверяют права на запросы и инвентарь, сохранение ответов, видимость, предотвращение повторных ответов, вес, вместимость предков, циклы, перенос поддеревьев и подготовку торгового комплекта. Адаптер сверялся с исходным Item Piles, commit `85ab971406623fb1c5d01eb1f093fe4855ede6e4`, включая его настройки и обработчики транзакций.

Отдельный DOM smoke-тест с имитацией документов Foundry проверил кнопки запроса, ответ владельца, помещение оружия в рюкзак и обновление состояний без ошибок. Он не заменяет реальный Foundry. Проверка в реальном многопользовательском мире Foundry 14 ещё требуется. Очереди запросов и редактирования инвентаря действуют в одном клиенте; это не серверная блокировка одновременных действий нескольких владельцев. Торговые транзакции выполняет Item Piles; его последовательная запись двух актёров не является атомарной транзакцией базы данных. Перед установкой экспериментальной версии сделайте копию мира.

Проверка перед выпуском: GM + игрок, обычный и независимый токен; публичный/GM/слепой запрос; закрытие запроса; покупка, продажа и отказ при нехватке денег; перенос и продажа рюкзака с двумя уровнями вложения; бесконечный ассортимент; перезагрузка мира; отключённый Item Piles.

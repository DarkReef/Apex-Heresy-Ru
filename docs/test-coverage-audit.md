# Тесты и покрытие: аудит 5 ноября 2026

Проверена ветка `codex/stability-audit` от `3321185`, Node **24.21.0**, Windows x64, 12 доступных логических процессоров. Финальный полный V8-прогон: **1109 passed, 0 failed, 0 skipped**, **10375.478 мс**. Итоговые числа ниже прочитаны из `coverage/test-audit/summary.json`; отчёт содержит отдельный знаменатель без сгенерированных данных. Это подтверждение автоматических проверок на моделируемых границах, а не приёмка многопользовательской игры.

## Что изменено

- `loadSystem` компилирует неизменяемый `vm.Script` один раз на тестовый процесс. Каждый вызов продолжает создавать отдельные globals, классы и реестр hooks; два новых теста проверяют отсутствие утечки состояния.
- Строки импортов заменяются пробелами с сохранением длины и переводов строк. VM получает абсолютный путь настоящего `script/dark-heresy.js`. Стек и V8 coverage теперь ссылаются на исходные строки. Контракт импорта использует ту же функцию преобразования вместо собственной копии regex.
- Синтаксис всех 75 runtime-файлов проверяется одним дочерним Node-процессом через `vm.SourceTextModule`, без исполнения браузерного кода. Дополнительный тест проверяет, что ошибочный второй файл действительно обнаруживается и называется в ошибке.
- Два прежних skip по пути `d:/Foundry/.../classic-level` устранены. Проверки происхождений и талантов используют проектную зависимость и временные копии LevelDB. Открытие исходных баз не требуется. Проверка BC-пакета отделена от быстрых unit-тестов в `bc-talent-pack.test.mjs`.
- Добавлены выбор наборов для TDD, воспроизводимый V8/LCOV-отчёт и CI-артефакты. CI настроен на Node 22 и 24; результат конкретного удалённого запуска нужно проверять отдельно.

## Команды

```sh
npm ci --ignore-scripts
npm test
npm run test:unit
npm run test:integration
npm run test:scenarios
npm run test:contracts
npm run test:combat
npm run test:inventory
npm run test:coverage
```

Для короткого цикла правки:

```sh
npm run test:unit -- --name ammunition
npm run test:unit -- --name rounding --watch
npm run test:combat -- --name effect-clock
npm run test:coverage -- --tier integration --output coverage/integration
```

`test:coverage` выполняет выбранные тесты и сохраняет `coverage/test-audit/tests.log`, `lcov.info` и `summary.json`. JSON содержит точную команду, версию Node, exit code, время, выбранные файлы, знаменатели покрытия и список runtime-файлов, которых V8 не зарегистрировал. `loadedScripts` сохраняет исходный полный результат V8; `loadedBehaviorScripts` исключает только явно перечисленный `generatedDataFiles: ['script/data/template-data.mjs']`. Обычные каталоги остаются в обоих итогах. Неуспешный тестовый прогон возвращает ненулевой код даже при сформированном отчёте. Каталог `coverage/` исключён из git.

## Source-regex и дубли

Инвентарь отмечает 95 поисковых индикаторов source-regex проверок в 27 файлах. Это не число бесполезных тестов: совпадения служат для ручной проверки.

Сохранены полезные контракты — наличие ключей локализации, кнопок шаблонов, синтаксис модулей и отсутствие опциональных расширений в архиве. Они не заменяют исполнение. Например, regex в `counter-attack.test.mjs`, проверяющий наличие `setLegacyFlag`, не доказывает списание только один раз; проверка `spendFatePoint` по тексту не доказывает сохранение документа; наличие строки −20 в подавлении не доказывает применение к нужной цели.

Убрана дублирующая реализация transform из теста импортов: теперь проверяется настоящая функция harness и сохранение смещений. Поведенческие регрессии карточки, боеприпасов, длительности и передачи GM остаются самостоятельными проверками. Никакие полезные проверки не удалялись ради процента.

## Что ещё требуется для статуса stable

Автоматический процент не подтверждает:

- запуск и обновление пакета на настоящем Foundry 14, работу миграций и editor/UI;
- браузерные выборы целей, размещение Regions, стены, высоты и допустимость ухода из Blast;
- настоящее взаимодействие GM/игрока, задержки sockets, переподключение, смену активного GM и сохранение после перезагрузки клиента;
- видимость скрытых целей, приватных бросков и служебных сообщений на реальных правах;
- MCP/Companion, доверие ключу и выполнение команд через подключённый клиент;
- мастер создания персонажа, загрузку стартового UI, погоду и комбинации всех расширений.

Эти пункты должны иметь отдельный журнал E2E/совместимости с версиями, конкретными действиями и результатами. Приёмку нельзя заменять названиями mock-тестов, ручной отметкой либо повышением порога покрытия.

# Живые проверки через Companion

Эти функции запускаются только по разрешению GM через Companion в настоящем клиенте Foundry. Они не входят в `npm test`: unit/integration с подменами не выдаются за браузерную приёмку.

`inventory.mjs` принимает уникальный `runId` и ID созданного для проверки Actor с флагом `flags.apex-heresy-ru.stabilityAudit`. Проверяет реальные документы, Item Piles и API магазина. Состояние и результаты сохраняются в `game.__apexStabilityAudit`; после перезагрузки его нужно восстановить из заранее сохранённого отчёта. Каждая проверка сохраняется сразу, включая случаи, когда последующий вызов отклонён.

`clock-regressions.mjs` создаёт собственные помеченные Actor/Scene/Tokens/ActiveEffects и удаляет их в `finally`. Combat остаётся только в памяти: удаление настоящего Combat в Foundry может затронуть глобальный реестр эффектов и другой бой. Проверка не утверждает, что отработала полная сетевая смена ходов.

`cleanup.mjs` получает записанное состояние, проверяет маркеры и удаляет только временные документы. Существующие сцены, персонажи, предметы и бои не удаляются. В конце восстанавливаются просмотренная сцена, выделение/цели и исходная политика Companion `runScriptMode=off`, `runMacroScriptMode=confirm`. Настройки доверия и ключи не меняются.

Перед тестом сохранить состав версий и SHA фактически обслуживаемых файлов; строка manifest может быть закэширована до перезапуска сервера. Для multiplayer требуется отдельно разрешённый временный игрок с доступом только к QA-персонажам/сцене. Пароль, данные мира и исходники ядра Foundry в отчёт репозитория не включать.
